# 工具、审批与 MCP

内置工具包括 `read_file`、`list_directory`、`search`、`write_file`、`replace_text`、`apply_patch` 和 `run_command`。启用工具后，只有能力明确支持工具调用的模型可以使用它们，实际执行仍受审批规则约束。

工作区的 `search` 跳过 Daphnis 会话存储目录。对话记录可通过受限的[历史回查工具](context_compaction.md#历史回查)访问。

## 文本附件

在 Web 输入框使用「+」选择文件，或把文件拖入输入区域。同名文件可以同时添加；标签旁的「×」移除待发送项。V1 支持常见 UTF-8 文本与源码，每次最多 10 个文件，单个不超过 128 KiB，总计不超过 256 KiB。图片、PDF、Office 文档、其他二进制文件及已知凭据文件会被拒绝。文本中仍可能含有敏感数据，发送前请检查。

发送后保存的是添加时读取的文件内容，历史显示文件名。附件正文可能发送给所选模型服务。较小的附件可在当前轮内联；较大的附件需要支持工具的模型，并在当前会话启用 `read_attachment` 和 `search_attachment`。这两个工具都是只读操作，遵循现有 ASK、AUTO、FULL 规则，只能访问当前会话关联的附件。

- `read_attachment(id, start_line, end_line)` 返回最多约 8 KiB 的带行号正文。还没读完时，用返回的 `next_line`、`next_column` 分别作为下次的 `start_line`、`start_column`。
- `search_attachment(query, id, limit)` 搜索字面文本，省略 `id` 可搜索当前会话的所有附件。结果只包含有限的匹配片段。历史压缩后，可通过 `history_read` 查询原始用户消息关联的附件名和 ID，正文仍从附件工具读取。

模型请求发往选定的模型服务，可能包含会话消息、文件内容和工具结果。模型响应、工作区文件和 MCP 工具结果都可能包含外部提供的内容，工具调用由本地规则校验和授权。

## 审批规则

Web 在输入框旁切换审批模式。启用 FULL 需要确认风险，取消会保留原模式。运行期间无法切换。

| 模式 | 执行方式 |
| --- | --- |
| `ask` | 所有可执行的工具调用都需人工确认。 |
| `auto`（默认） | 自动执行规则允许的操作，其余需人工确认。可在审批支持时授予会话信任。 |
| `full` | 跳过逐次人工审批，允许读取 `.env` 等敏感文件，自动执行受支持的开发命令和 MCP 调用。 |

参数校验、硬编码禁止、内置文件工具的工作区写入边界和执行前校验在三种模式下均生效。`ask` 和 `auto` 保留凭据路径保护，并对允许的工作区外访问、无法检查访问范围的命令和内置文件写入要求逐次确认。非交互执行会拒绝所有需要审批的调用。

模式和信任保存在运行进程内。新建会话或重启后使用 `auto`，恢复已有会话时沿用进程当前模式。信任绑定会话和工具，同一 MCP 工具的后续调用可使用不同参数。新会话拥有独立的信任范围，切换到 `ask` 会清除已有信任。MCP 服务断开、重连或目录变化时会撤销相关信任。

## 文件、补丁与命令边界

- **文件读取和搜索**在 `ask` 和 `auto` 下检查原始及解析后的路径，阻止读取常见凭据文件。`full` 允许读取这些文件，内容可能随工具结果发给模型服务。多硬链接限制和搜索范围限制仍然生效。`.env.example` 可作为模板读取，目录列表和文件名搜索仍可能显示敏感文件的名称。
- **新建文件**使用 `write_file(path, content)`，传入完整 UTF-8 文本，可为空，最大 1 MiB。目标须位于当前工作区内，父目录须已存在，路径禁止 `..` 和符号链接目录。目标已存在时返回 `file_exists`。工具先写入并同步暂存文件，再以无覆盖方式原子发布。发布后的校验失败会以 `partial: true` 报告可能已创建的文件。
- **小范围修改**使用 `replace_text(path, old_text, new_text)`。只替换工作区内 UTF-8 文件中唯一的原文匹配，`old_text` 必须非空，`new_text` 可为空。没有匹配时返回 `text_not_found`，多处匹配时返回 `ambiguous_match`。源文件与结果均限制为 1 MiB。工具拒绝符号链接、多硬链接文件及受保护的凭据文件，并使用补丁的原子写入和冲突检查。多处或复杂修改使用 `apply_patch`。
- **补丁**使用普通 unified diff，要求原文精确匹配。工具检查工作区和父目录身份，并通过无覆盖方式安装变更。替换已有文件时，原路径可能短暂缺失。遇到冲突时，无法原位恢复的版本会留在工具报告的暂存位置。进程异常退出留下的 `.daphnis-*.tmp/original` 可用于恢复。多文件写入可能部分生效，具体路径见工具结果。
- **命令**以 argv 执行，并过滤已知凭据环境变量。`auto` 仅自动放行通过参数和路径检查的受信任系统命令 `pwd`、`uname`、`echo`。`cat`、`ls`、`head`、`tail`、`wc` 等可能访问文件的命令在 `auto` 下需确认。审批显示实际执行的 argv。Shell 表达式、内联解释器执行和部分破坏性命令受硬编码限制。
- **高危命令**在审批前统一拦截，包括强制递归删除、删除工作区根目录或已知的系统关键目录、工作区外递归删除、强制 Git 清理、硬重置、强推、磁盘格式化、提权和关机重启。
- **进程与文件系统隔离**依赖操作系统。获准运行的程序拥有当前用户的权限，可能读写文件、访问网络或启动进程。硬编码检查约束直接调用，脚本、开发命令和 MCP 服务仍可能间接产生同类副作用。外部命令启动时会自行解析路径，同用户的并发进程仍可能替换路径。超时或取消时会尝试终止原进程组并回收直接子进程。脱离进程组的后代和已产生的外部副作用可能保留。

## MCP 配置与生命周期

在 Web 顶部打开「MCP」，可手动添加 stdio 或 Streamable HTTP 服务，并对其编辑、启用、禁用、重连或删除。服务标识用于生成稳定的工具名，创建后固定。启用状态独立于会话，具体工具仍在「工具」面板内选择。

配置保存在 `~/.daphnis/mcp.json`。Web 启动时恢复已启用的连接，失败的服务保留配置和错误状态，可在面板重连。运行中的 Turn 会保留本轮工具定义快照，连接和配置变更须等任务停止后执行。

首次使用时可在 `.env` 或服务端环境设置 `DAPHNIS_MCP_CONFIG=./legacy-mcp.json` 导入旧配置。只有尚未创建持久化配置时才会导入。旧文件的相对路径以启动目录为准，其中相对 `cwd` 以该文件所在目录为准。`env` 将子进程变量名映射到本地环境变量名。

```json
{
  "servers": {
    "demo": {
      "transport": "stdio",
      "command": "python",
      "args": ["server.py"],
      "cwd": "./examples",
      "env": {"SERVICE_API_KEY": "LOCAL_SERVICE_KEY"}
    },
    "remote": {
      "transport": "streamable_http",
      "url": "https://example.com/mcp",
      "auth": {"type": "bearer", "env": "REMOTE_MCP_TOKEN"}
    }
  }
}
```

```sh
DAPHNIS_MCP_CONFIG=./legacy-mcp.json uv run --locked --extra web daphnis-web
```

stdio 程序以当前用户权限启动，应使用可信程序。手动添加的 Streamable HTTP 服务使用最终端点，远程地址要求 HTTPS，回环地址允许 HTTP。认证可省略，启用时由指定环境变量提供 Bearer Token。凭据请放在服务端环境中，避免写入启动参数或 URL。MCP Server 决定其内部如何读写文件、使用凭据或访问网络，Daphnis 的审批只控制是否发起工具调用。

支持工具变更通知的服务可自动刷新目录，相关的自动授权仍可被撤销。代码可通过 [Operations](operations.md#接口速查) 查询和管理连接。

对支持工具的模型，首次显式连接新服务时会默认启用发现的工具。从历史恢复的会话和此后新建的会话优先使用保存的选择。恢复会话只恢复启用偏好，MCP 连接需显式配置。掉线和目录变化会保留启用偏好，只有在线且已启用的工具会提供给下一轮。可以在 Web 的「工具」面板启用新发现的工具。

MCP 工具的文本和结构化结果共用 64 KiB 的 UTF-8 JSON 预算，预算在 SDK 解码后生效。超限时会标记省略的字段。

### 在线发现

在「MCP → 发现」输入至少 3 个字符，搜索[官方 MCP Registry](https://registry.modelcontextprotocol.io)。结果显示各服务的最新版本。选择一项可查看来源、连接地址和本地软件包信息。选择支持的远程地址，按需填写 Bearer Token 的环境变量名，再确认添加。

在线发现可添加使用默认 HTTPS 端口的公网 Streamable HTTP 服务，连接会校验 DNS 解析结果并阻止重定向。支持无认证或 Bearer Token。OAuth、自定义认证头、地址模板和 SSE 服务不能通过发现添加。npm、PyPI 等软件包只展示安装信息，需自行安装后再配置 stdio。Registry 查询失败时，已配置的 MCP 服务仍可使用。

### MCP Prompts

在输入框旁点击「Prompts」，展开提供 [MCP Prompts](https://modelcontextprotocol.io/specification/2025-11-25/server/prompts) 的已连接服务。选择模板并填写参数，点击「生成预览」后，参数会发给所选服务。逐条核对或编辑正文，再点击「运行」。普通输入框及待发送附件独立保留。

一次运行对应一轮任务。模型按预览顺序收到原生 User 或 Assistant 文本消息，工具调用遵循当前审批模式。当前模型接口要求最后一条消息为 User。预览以 Assistant 结尾时，可点击「补充 User 消息」再运行。含图片、嵌入资源等内容的结果可以查看类型，整个 Prompt 暂时无法运行。

Web 会在预览中隐藏检测到的凭据。运行使用预览中确认的文本。运行组最多 64 条消息，文本和角色的 UTF-8 JSON 大小上限为 64 KiB。生成预览和执行分开进行，执行时一次保存实际消息及来源名称。失败后可从历史中的 Prompt 组重试，重试使用保存的消息快照。后续工作见 [MCP 路线图](mcp_roadmap.md)。

## Web 边界

Web 服务仅绑定 `127.0.0.1`，校验请求的 Host、命令和事件连接的 Origin，并要求每次启动生成的访问令牌。浏览器把令牌保存于当前标签页的会话存储。模型连接和密钥由服务端配置，浏览器通过固定命令提交任务和审批，默认审批模式由 Core 决定。

Bridge 对浏览器快照及缓存的调试记录做凭据脱敏，覆盖已配置的模型密钥、Web 令牌和常见凭据格式。实时流式文本在发往浏览器前脱敏。脱敏范围受已知值和匹配规则限制，调试数据仍可能包含工作区内容。Core 历史与事件独立于浏览器脱敏规则。
